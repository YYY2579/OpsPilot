# 决策记录 001 · 代码组织与上游依赖策略

> M0-3 ｜ 2026-09-12 ｜ 状态：已定
> 关联：交接文档 §九决策 4、开发任务拆解 M0-2/M0-3

## 决策

**OpsPilot 独立建仓**（本仓库，`OpsPilot/`），上游 OpenHands 以**固定版本的依赖**引入，`upstream/` 目录仅作参考与调试，**永不直接改代码**。

## 理由

1. **差异化零侵入**：OpsPilot 的工作量（FastAPI 资源后端、运维工具、三栏前端）没有一样需要改 OpenHands 核心（交接文档 §6.2/6.3）。fork 只会带来长期合并负担。
2. **上游日活跃且 Beta 组件快速演进**：组装式 + pin 版本让我们随时可以跟随上游修复，升级是一次显式决策（单独任务），而不是顺手 `npm update`。
3. **确需改上游**：先在其仓库提 PR（MIT 欢迎贡献），合并前本地以 patch 文件过渡并登记 issue。

## 本仓库约定

- `upstream/` 已在 `.gitignore` 中排除（浅克隆快照，仅供阅读、调试、复现问题；M0-4 源码索引以它为准产出 `docs/源码索引.md`）
- 后续代码目录：后端 `backend/`（FastAPI + SQLite）、前端 `frontend/`（React 19 + TS + Vite + Tauri，M5-1 脚手架时创建）、工具包随 backend 一起
- 每个 milestone 的验收证据入 `docs/` 或测试产物，不入库密钥（`key.txt` 已忽略）
