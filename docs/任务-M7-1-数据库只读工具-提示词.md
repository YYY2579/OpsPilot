【开始前必须阅读的文件（按顺序，务必真读）】
1. backend/ops_pilot/tools/_base.py            —— Executor 骨架 + JsonObservation（你要照它的结构）
2. backend/ops_pilot/tools/sshcmd.py           —— run_checked / run_lenient / tail / clamp / CollectionError

6. backend/ops_pilot/security/guard.py         —— TOOL_LEVELS 风险等级登记表

8. backend/docs（如果有）或 docs/OpsPilot-需求开发文档.md 的 §A5.2 工具清单、§A6.4 凭据边界、§A6.5 权限档位
   （文档在 C:\Users\25791\Desktop\OpsPilot\docs\ 下）

【要实现的 5 个工具（名字不得改动）】
1. list_databases      —— 列出实例上的数据库及大小
2. list_tables         —— 列出指定库的表（含行数与引擎）
3. describe_table      —— 查看表结构（列、类型、可空、键、默认值）
4. query_readonly      —— 执行**只读** SQL（仅允许 SELECT / SHOW / EXPLAIN / DESCRIBE）
5. explain_sql         —— 对给定 SELECT 执行 EXPLAIN，返回执行计划

【硬约束（违反任何一条都算不合格）】
1. **命名不得改**：工具名必须是上面 5 个；Observation 字段名一旦定义就不要中途改。
2. **Action 只允许逻辑标识**：每个 Action 的第一个字段固定为 `database_id: str`
   （如 `mysql-prod`），**绝不允许出现 host / port / username / password / dsn 字段**。
   凭据只允许在 Executor 内部解析（见第 4 条）。
3. **全部只读**：`ToolAnnotations(readOnlyHint=True)`。第 4 个工具 `query_readonly` 必须实现
   硬性 SQL 白名单校验（见下），不允许依赖"用户会自觉"。
4. **凭据纪律**：新增 `ops_pilot/db/credentials.py`（或放在你有理由的位置），提供
   `DbCredentialResolver`：把 `database_id` 解析成连接信息，来源为环境变量：
       OPSIPLOT_DB_{DATABASE_ID}_HOST / _PORT / _USERNAME / _PASSWORD / _DATABASE
   其中 `{DATABASE_ID}` 需规范化：大写，`-` 与 `.` 换成 `_`（`mysql-prod` → `MYSQL_PROD`）。
   解析失败抛 `CredentialError(kind, detail)`，kind 只能是 "missing" 或 "incomplete"。
   **凭据解析结果只允许在 Executor 内使用，禁止写入 Action / Observation / 日志。**
   本项目已有 `ops_pilot/credentials.py` 的 `CredentialError` 与 `SECRET_PLACEHOLDER="<secret-hidden>"`，
   请复用它们，不要另造一套。
5. **分层与可测性（重要）**：连接层与解析层必须分开，这样单测不需要真的连数据库：
   - `ops_pilot/db/client.py`：定义 `DbRunner` 协议
         class DbRunner(Protocol):
             def query(self, sql: str, params: tuple = (), limit: int = 200) -> tuple[list[str], list[tuple]]: ...
             def close(self) -> None: ...
     并给出 `PymysqlRunner` 实现（**pymysql 延迟导入**，与现有 ssh/client.py 延迟导入 paramiko 的做法一致）。
     连接失败/权限错误要抛 `DbError(kind, detail)`，kind ∈ {"auth", "network", "sql"}。
   - 每个工具的 Executor 只依赖 `DbRunner`，不直接 import pymysql。
6. **异常判断在 Executor 内完成**（这是本项目的既定原则，不要交给模型）：
   每个 Observation 都必须有 `anomalies: list[dict[str, str]]`，元素形如
   `{"item": "...", "level": "warning"|"critical", "hint": "..."}`。
   具体要求：
   - `list_databases`：单库 > 50 GB → warning；> 200 GB → critical
   - `list_tables`：表数量 > 500 → warning（提示可能是分表/设计问题）
   - `describe_table`：无主键的表 → warning（hint 里写明"无主键，写操作风险高"）
   - `query_readonly`：返回行数达到 limit（被截断）→ warning；执行耗时 > 3s → warning
   - `explain_sql`：出现 `type=ALL` 且 `rows` > 10000 → warning（hint 提示"全表扫描"）
   - 任何工具：捕获到 DbError 时不要塞进 anomalies，而是**抛 ValueError**（框架会把
     ValueError 转成 AgentErrorEvent），错误信息必须能区分 auth / network / sql。
7. **Executor 的错误转换**：与你参考的 `SshReadOnlyExecutor` 一致 —— 捕获
   `DbError / CredentialError` 后 `raise ValueError(f"DB {kind}: {detail}")`。
8. **不要写任何写操作工具**（INSERT/UPDATE/DELETE/DDL 一律不做，也不要做"预留接口"）。
9. **不要修改现有文件的行为**，只允许在这 3 处做"增量登记"：
   - `tools/register_all.py`：把 5 个名字加入 `READONLY_TOOL_NAMES`
   - `security/guard.py`：把 5 个名字加入 `TOOL_LEVELS`，等级一律 `RiskLevel.L1`
   - 如需新依赖（pymysql），写进 `backend/pyproject.toml` 的 dependencies 并 pin 版本
10. **不要碰**：`upstream/` 目录、`frontend/` 目录、任何 Tauri 相关内容。

【query_readonly 的 SQL 白名单（必须实现，不能省）】
- 先做**规范化**：去掉前后空白与结尾分号，压缩连续空白，转小写做前缀判断
- 只允许以 `select` / `show` / `explain` / `describe` / `desc` 开头
- 显式拒绝（即使在开头）包含以下任一关键字的语句：
    insert / update / delete / drop / truncate / alter / create / replace / grant / revoke /
    rename / load data / into outfile / into dumpfile / lock tables / unlock tables / call / set
- 多条语句（出现 `;` 后还有非空内容）一律拒绝
- 自动追加 `LIMIT`：若用户 SQL 里没有 limit，则追加 `LIMIT {limit}`（limit 默认 200，上限 1000）
- 拒绝时抛 `ValueError("只读模式不允许该语句：<原因>")`
