## 二、M0 开工前必须装好的（按顺序）

### 2.1 WSL2 + Ubuntu 24.04（Windows 必须，macOS/Linux 跳过）

OpenHands 官方在 Windows 上依赖 WSL2，不要试图在原生 Windows Python 里跑全栈。

```powershell
# 管理员 PowerShell
wsl --install -d Ubuntu-24.04
wsl --set-default-version 2
wsl --status          # 确认默认版本为 2
```

### 2.2 Git

```powershell
winget install Git.Git
git --version         # ≥ 2.40
```

### 2.3 Node.js 24

**实测要求是 Node ≥ 24**：`upstream/openhands/package.json` 的 `engines` 字段为 `{"node": ">=24"}`（agent-canvas 1.18.0），本机已用 **24.19.0** 跑通 M0-1。早期上游资料写的 22.12+ 已被 `engines` 覆盖，**以代码为准**。

```powershell
winget install OpenJS.NodeJS
node -v               # 需 ≥ 24（本机 24.19.0 已验证）
npm -v
```

### 2.4 Python 3.12 + uv

OpenHands 指定 Python 3.12。用 uv 管理版本，避免污染系统 Python：

```powershell
winget install astral-sh.uv
uv python install 3.12
uv python list        # 确认 3.12.x 已安装
uv --version
```

### 2.5 Docker Desktop

```powershell
winget install Docker.DockerDesktop
docker --version
docker compose version
```

装好后设置里勾选 **Use the WSL 2 based engine**。

### 2.6 LLM API Key

至少准备一个可用的 Key（效果图中示例是 DeepSeek-V3，实际任意一家都行，SDK 走 LiteLLM 支持 100+ 提供商）：

```text
DEEPSEEK_API_KEY=sk-xxxx        # 或 ANTHROPIC_API_KEY / OPENAI_API_KEY
```

> 建议**只读探索**用便宜模型，分析与审批用强模型 —— 这是规格 §A3 的多模型路由设计。

| 里程碑 | 需要追加安装 | 命令 |

```powershell
winget install Microsoft.EdgeWebView2Runtime
```

## 五、项目初始化（对应任务拆解 M0-1 / M0-2 / M0-3）

### 5.1 跑通原版（M0-1）

```powershell
npm install -g @openhands/agent-canvas@1.18.0
agent-canvas
# 打开 http://localhost:8000，确认三服务栈起来了
```

> agent-server 的版本由 `upstream/openhands/config/defaults.json` 里的 **1.46.0** 通过 `uvx` 自动拉起，这就是为什么必须先装 uv。
> 若想用 Docker 方式（更隔离）：
> ```powershell
> mkdir -p ~/projects ~/.openhands
> docker run -it --rm -p 8000:8000 `
>   -v ~/.openhands:/home/openhands/.openhands `
>   -v ~/projects:/projects `
>   ghcr.io/openhands/agent-canvas:1.18.0
> ```

### 5.2 版本基线落档（M0-2）

跑通后执行并记录：

```powershell
npm ls -g @openhands/agent-canvas
# agent-server 版本来自 upstream/openhands/config/defaults.json → versions.agentServer
```

把实际值回填进 `README.md` 的版本基线表。**依赖一律用 `=` 固定，禁止 `^` 与 `>=`。**

### 5.3 建自己的仓库（M0-3）

```powershell
cd C:\Users\25791\Desktop\OpsPilot
git init
git add .
git commit -m "chore: 项目初始化（规格 / 原型 / 效果图 / 上游参考）"
```

`upstream/` **不要**提交进自己的仓库（体积大且属于第三方），改为在 `.gitignore` 里排除，并在 README 里记录它的 commit 与获取方式：

```gitignore
upstream/
```

```powershell
# 上游参考的复现方式（写进 README 即可，不进仓库）
git clone --depth 1 https://github.com/OpenHands/OpenHands.git upstream/openhands
git clone --depth 1 https://github.com/OpenHands/software-agent-sdk.git upstream/software-agent-sdk
```

### 5.4 记住一个依赖坑（上游自己标注的）

**`agent-client-protocol` 必须锁 `<0.11`**：`acp 0.11.0` 重排了 ACP `prompt()` 参数，会让 SDK 的 ACP 客户端报
`ACP error: 2 validation errors for PromptRequest`。
装任何 OpenHands 相关 Python 依赖时都要带上这个约束。

## 六、环境变量与密钥

| 变量 | 用途 | 必需 |
|---|---|---|
| `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | 模型调用 | ✅ |
| `LOCAL_BACKEND_API_KEY` | 本地后端访问令牌（对外暴露时必须设强值） | 对外暴露时 |
| `OH_SECRET_KEY` | 密钥库加密主密钥（换了它，旧数据无法解密） | 启用 SecretRegistry 后 |

> 密钥**不要**写进仓库。用 `.env`（已 gitignore）或系统密钥环 —— 这正是规格 §A6.4 的要求，从第一天就遵守。

## 七、坑（都实际踩过或有明确出处）

| 坑 | 说明 | 对策 |
|---|---|---|
| **项目路径不要含中文或空格** | `C:\Users\25791\Desktop\OpsPilot\` 已是纯 ASCII，**保持这样**。含中文的路径会让部分工具链（shell shim、脚本）出问题 | 新建目录一律 ASCII |
| Windows 上跑 OpenHands | 必须走 WSL2，原生 Windows Python 跑全栈不在官方支持范围 | §2.1 |
| 端口占用 | 8000（前端/ingress）、18000（agent-server）、18001（automation） | 起服务前确认这三个端口空闲 |
| Node 多版本冲突 | 机器上若同时有多个 Node 版本，切到 24 再 `npm install` | `nvm use 24.19.0` |
| PowerShell 执行策略 | `npm install` 后脚本可能被策略拦 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| 防火墙 | 对外暴露 8000 时必须配 HTTPS 与强 `LOCAL_BACKEND_API_KEY` | MVP 只在本机/内网跑 |
| 依赖浮动升级 | 上游活跃，Beta 组件多 | 全部 pin 具体版本，升级走单独任务 |
| 磁盘与内存 | node_modules + Docker 镜像 + WSL 镜像合计约 10–15 GB；建议 16 GB 内存 | 清理 `docker system prune` |
