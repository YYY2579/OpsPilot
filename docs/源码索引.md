## 0 · 三条必须先知道的修正（影响规格与前端设计）

| # | 结论 | 影响 |
|---|---|---|
| **0.1** | 框架没有 `AgentStateChangedObservation`。前端感知状态变化的机制是 **`ConversationStateUpdateEvent`**（`event/conversation_state.py:18-104`），字段 `key`（字段名或 `"full_state"`）+ `value`，经 WebSocket 推送；状态本体是 `ConversationState.execution_status` | 规格 §C 表与前端 §6 状态映射需改：订阅 `key="execution_status"` |
| **0.2** | 框架的执行状态只有 **8 个值**（见 2.2），不是我们规格里的 16 个。我们的 16 态是**业务层投影**，必须写一层映射 | 前端不做 16 态判断，只消费 `execution_status` + 事件类型推导业务态 |
| **0.3** | 凭据脱敏的真实占位符是 **`<secret-hidden>`**，不是 `***` | 规格 §A6.4 与验收断言需同步修改 |
| **0.4** | agent-server 的 WebSocket 是**原生 WebSocket**，不是 Socket.IO；会话级推荐端点 `/sockets/session/{id}`，帧协议带 `seq` 支持断线续传 | 前端不要引 socket.io-client |
| **0.5** | Node 要求 **≥24**（`upstream/openhands/package.json` → `engines.node: ">=24"`），非早期资料的 22.12+ | 环境文档已修正 |
