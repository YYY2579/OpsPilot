## 二、关键路径与并行线

```text
A 线（后端）  M0-4 → M1 → M2 → M3 → M4 ─┐
                                        ├──→ M6（打通）→ M7
B 线（前端）  M0-5 → M5（纯 mock） ─────┘
```

- **A / B 两条线可以完全并行**，解耦点是三个契约：§A10 的 API、WebSocket 事件字段、§A7.1 的 16 态映射。前端在 M5 阶段用 mock 数据先把像素对齐，**不等后端**。
- **关键路径是**：`M0-4 源码索引 → M1-3 get_server_health → M2-5 权限档位 → M3-2 确认策略 → M6-2 事件流 → M6-3 审批闭环`。这条链上任何一个任务卡住都会推迟可演示时间。
- **前端不是关键路径**，但它是工作量最大的一块（见 §风险），所以越早并行越好。

## 十一、横切要求（贯穿所有里程碑）

| 要求 | 说明 | 落点 |
|---|---|---|
| **凭据永不入 prompt** | 每加一个工具都要重新跑一次"打印 prompt 搜密钥" | §A6.4 |
| **异常判断在 Executor 内** | 不交给 LLM，否则输出不稳定、不可测 | §A5.2 |
| **每个工具有单测** | schema 稳定性 + 异常路径 + 超时 | §A14 |
| **审计不缺席** | 新增任何"自动执行"能力都要先回答"怎么记" | §A6.5.5 |
| **上游不漂移** | 任何新依赖都 pin 具体版本；升级是显式决策不是顺手 `npm update` | README 版本基线 |

## 十三、接下来立刻做的三件事

1. **M0-1 跑通原版** —— 这是所有事的前提，跑不通后面全部免谈。
2. **M0-4 源码索引** —— 把规格里所有 ⚠️ 待核实项一次性消掉，M1/M3 才有把握。
3. **M0-5 拍四个决策** —— 特别是桌面封装和菜单栏实现方式，直接影响 M5 的脚手架选择。

> M0 完成后，A 线（M1）和 B 线（M5-1）可以同时开两条线。
