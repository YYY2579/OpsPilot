# 前端实现规格与开发提示词

> 本文件是 `OpsPilot-需求开发文档.md` 的**前端落地补充**，用于把 `assets/` 的效果图 1:1 还原成代码。
> 配套参考实现：`prototype/` 下的 10 个 HTML 文件（每个文件就是对应状态的可运行 DOM 结构）。
>
> **使用方式**：把本文件 + `OpsPilot-需求开发文档.md` + `assets/` 一起交给编码 AI，按第 10 节的提示词开工。

---

## 1. 技术栈与工程约定

| 项 | 定稿 |
|---|---|
| 框架 | React 19 + TypeScript |
| 构建 | Vite |
| 样式 | Tailwind CSS（配合下方 CSS 变量；不引组件库主题） |
| 路由 | React Router 7 |
| 服务端状态 | TanStack Query |
| 客户端状态 | Zustand |
| 桌面封装 | Tauri（打包 Windows / macOS / Linux） |
| 图标 | 内联 SVG，`stroke="currentColor"`，尺寸 13px（导航）/ 14px（按钮）/ 15px（卡片标题） |
| 字体 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif` |
| 等宽字体 | `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`，用于命令 / 日志 / 代码 / ID |

**命名约定**：组件用 PascalCase；CSS 变量用 `--` 前缀；状态枚举值**必须**与需求开发文档 §A7 完全一致（`RECEIVED` / `WAITING_APPROVAL` / …），**禁止**在代码里另起小写别名。

### 3.1 响应式断点（必须实现，见需求开发文档 §B12.2）

**总原则：任何窗口尺寸下都不允许横向滚动条，也不允许内容被裁切。面板让位优先级为「右栏 → 左栏」。**

```css
/* 侧栏宽度随窗口收缩 */
@media (max-width:1439px){ .sidebar{width:236px} .rail{width:288px} }
/* 右栏自动收起为 44px 图标条 */
@media (max-width:1279px){
  .railmini-auto{display:flex}   /* 44px 竖条 */
  .rail-auto{display:none}
  .sidebar{width:220px}
}
@media (max-width:1023px){
  .sidebar{width:200px}
  .stream{padding:12px 16px}
  .composer{padding:0 16px 13px}
}
/* 左栏也自动收起为 48px 图标条 */
@media (max-width:959px){
  .sidemini-auto{display:flex}
  .sidebar-auto{display:none}
}
/* 超宽屏：聊天列限宽居中，避免一行文字横跨 1900px */
@media (min-width:1700px){ .stream{max-width:1120px} .composer{max-width:1120px} }
/* 纵向：聊天流内滚动，输入框永远贴在底部可见 */
@media (max-height:840px){ .stream{padding:11px 18px;gap:10px} }
@media (max-height:720px){
  .topbar{height:50px} .ctx{height:36px}
  .stream{padding:9px 16px;gap:8px} .composer{padding:0 16px 11px}
  .railin{padding:9px 11px;gap:8px} .sec{padding:9px 10px}
  .welcome h2{font-size:20px} .quick{margin-top:14px}
}
```

**三条硬要求**

1. **纵向**：`.stream` 用 `overflow-y:auto`，输入框 `flex:none` 常驻底部。内容再长也不裁切、不把输入框顶出屏幕。
2. **横向**：面板收起后由 44px（右）/ 48px（左）图标条承接，**不是消失**——图标条保留概览/工具/任务/日志，以及资源分类入口。
3. **超宽屏**：`.stream` 与 `.composer` 同时限宽并 `margin:0 auto` 居中（两者限宽值必须一致，否则会错位）。

**状态区分**：窄窗口的**自动**收起与用户**手动**收起是同一视觉形态，但手动收起后窗口变宽仍须保持收起，直到用户手动展开。

│   │   └── <ProjectRow name env />

│   └── <Composer placeholder quickActions mode model think perm disabled>
│       ├── <DangerBanner />                     // 仅 perm=完全访问 时出现
│       └── <ComposerControls perm onPerm model onModel think onThink mode onMode onSend />

## 5. 组件逐个规格

### 5.0 `<MenuBar>`（桌面标题栏，30px）

| Prop | 取值 |
|---|---|
| `openMenu` | `null` \| `文件` \| `编辑` \| `视图` \| `设置` \| `帮助` |
| `onAction` | (menu, item) => void |
| `platform` | `win` \| `mac` —— 决定快捷键渲染为 `Ctrl` 还是 `⌘` |

- 结构：`[OP] OpsPilot` 品牌区（右侧 1px 分隔线）→ 五个菜单项 → 弹性空隙 → 窗口控制 `─ □ ✕`
- 菜单项高 22px，7px 左右内边距；展开时该项 accent 底色 + 白字
- 下拉面板：`position:absolute; top:24px`，`min-width:248px`，`--panel` 底 + `--border2` 边框 + 9px 圆角 + 投影；菜单项高 26px，快捷键右对齐、`--text3` 色
- 分隔线：`1px --border`，上下 5px 外边距
- **快捷键列表**（Windows 记法，macOS 渲染成 ⌘）：

| 菜单 | 菜单项（带快捷键） |
|---|---|
| 文件 | 新建窗口 `Ctrl+Shift+N`、新聊天 `Ctrl+N`、打开文件夹… `Ctrl+O`、保存会话记录 `Ctrl+S`、导出当前报告… `Ctrl+Shift+E`、关闭窗口 `Ctrl+W`、退出 OpsPilot `Ctrl+Q` |
| 编辑 | 撤销 `Ctrl+Z`、重做 `Ctrl+Shift+Z`、剪切 `Ctrl+X`、复制 `Ctrl+C`、粘贴 `Ctrl+V`、删除 `Del`、全选 `Ctrl+A`、查找… `Ctrl+F` |
| 视图 | 切换左侧栏 `Ctrl+B`、切换右侧面板 `Ctrl+Alt+B`、切换底部面板 `Ctrl+J`、打开终端 `` Ctrl+` ``、后退 `Alt+←`、前进 `Alt+→`、放大 `Ctrl+=`、缩小 `Ctrl+-`、重置缩放 `Ctrl+0`、全屏 `F11`、浅色 / 深色主题 `Ctrl+Shift+L` |
| 设置 | 偏好设置… `Ctrl+,`、模型与密钥、连接与凭据、主题、语言、导入 / 导出配置 |
| 帮助 | 文档 `F1`、键盘快捷键 `Ctrl+K Ctrl+S`、系统状态、检查更新…、关于 OpsPilot |

> 桌面壳建议：Tauri 下由 Rust 侧实现菜单（原生菜单或自绘），文件/编辑类系统动作映射到 `tauri::menu`；视图类动作改为前端状态切换。**不要只画不动**——菜单项必须真正触发对应行为。

### 5.1 `<TopBar>`（56px）

| Prop | 取值 |
|---|---|
| `workspace` | 当前工作区名 |
| `task` | 当前任务名，如 `分析 CPU 高负载原因` |
| `state` | `run` \| `wait` \| `done` \| `fail` |
| `panelCollapsed` | boolean |
| `theme` | `dark` \| `light` |
| `onToggleTheme` | () => void |

- 左：**工作区名 + 下拉箭头**（Logo 已上移到菜单栏品牌区，此处不再重复）
- 中：任务名 + 状态胶囊。**状态色必须区分**：`run` 用 accent、`wait` 用 warn、`done` 用 ok、`fail` 用 err，胶囊内带 6px 圆点
- 右：**主题切换按钮** → 面板折叠时额外出现一个面板按钮（accent 色）→ **设置齿轮** → 头像（26px 圆）
- **顶部栏不得出现模型名与 Agent 模式**——它们已下移到 Composer（见 5.9）。

### 5.2 `<Sidebar>`

- 搜索框：30px 高，右端 `Ctrl K` 键位提示
- **分两组，顺序固定，各带一个分组小标题**（10px、`--text3`、字距 .6px）：
  - **资源** → 服务器、数据库
  - **工作** → 项目、任务历史、收藏
- **分组不可合并**：服务器/数据库是"连过去的外部资源"，项目/任务历史/收藏是"我自己的东西"。混在一列会让人分不清层级。
- 服务器行：名称 + IP（小字，两行结构）+ 右侧环境标签。**环境标签色**：生产 err、测试 warn、开发 text3
- 项目行：图标用文件夹、名称 + 环境标签，**不显示 IP**
- 选中行：背景 `--panel2` + 左侧 2px `--accent` 竖条
- 数据库被选中时，**在该数据库下展开资源树**：库名 + 表数量 → `Tables` / `Views` / `Procedures` / `Functions`（可折叠，带计数）→ `Query Console`（带终端图标）
- 底部 2×2 网格按钮，首项「新建连接」为 accent 实心
- 第一版资源树支持折叠/展开；右键菜单与拖拽分组**可后置**

### 5.3 `<PlanCard>`（步骤链）

- 每步一行：状态图标 + 步骤名 + 右侧状态文字
- 图标语义：`✓` ok 已完成 ｜ `●` accent 进行中 ｜ `○` text3 待执行 ｜ `✕` err 失败
- 行间用 `1px dashed --border` 分隔（最后一行无）
- 已完成步骤必须显示耗时（如 `1.2s`）
- **可折叠**：折叠后只显示标题行 + 「N 项 · 已完成 M 项」

### 5.4 `<ToolCard>`

折叠态（一行）：工具名（600）+ 中文说明（text3）+ 右侧 状态 + 耗时 + 风险徽标 + 展开箭头

展开态（**8 个字段全部必显示**，缺一不可）：

| 字段 | 说明 |
|---|---|
| 工具名称 | 等宽 |
| 参数 | 等宽 JSON |
| 目标资源 | 显示 `名称 (server_id)` |
| 执行命令 | 等宽 |
| 标准输出 | 等宽代码块，背景 `--bg`，边框 `--border` |
| 错误输出 | 同上；为空时显示 `(空)` 且用 text3 |
| 执行耗时 | 如 `1.5s`；超时用 err 色 |
| 风险等级 | 徽标，如 `L1 · 只读` |

**状态五种**：`等待执行`(text3) / `执行中`(accent, 带 spinner) / `已完成`(ok) / `执行失败`(err, 卡片边框转 err、卡头底色转 err-soft) / `等待批准`(warn)

> 大段输出（>30 行）截断并给「展开全部」。

### 5.5 `<ApprovalCard>`（本产品最核心的差异点）

- 容器：`--warn` 边框 + `--warn-soft` 底色 + 9px 圆角
- 标题行：盾牌图标 + **「需要你的批准」**，字重 700，`--warn` 色
- 一行根因摘要（12px，text2）
- 字段与顺序固定：**操作 / 目标（含 `server_id`）/ 风险等级 / 执行内容 / 预计影响 / 回滚方案**
- 风险等级用徽标，**同时显示 L 级和中文**（如 `L3 · 中风险`）
- 按钮四枚，顺序与视觉权重固定：
  `查看命令`(次) ｜ **`批准执行`(主，accent 实心)** ｜ `拒绝`(次) ｜ `修改方案`(warn 描边)
- **禁止**只给一个"执行"按钮
- 触发时机：由 OpenHands `ConfirmationPolicy` 返回需确认时进入 `WAITING_APPROVAL`
- 卡片出现时输入框转禁用（55% 透明度）并提示「等待你批准后继续…」

### 5.6 `<SummaryCard>`

- 容器：`--ok` 边框，卡头 `✓ 任务已完成`
- 四行字段：**问题 / 原因 / 处理 / 验证**
- 下方 3 个数值卡（改造前 → 改造后，绿色）
- `后续建议` 区：1/2/3 编号列表
- 三个按钮：`按建议整改`(主) / `导出报告` / `查看完整执行记录`

### 5.7 `<ErrorCard>`

- 容器：`--err` 边框，卡头 err-soft 底 + ✕ 状态
- 至少给出三块：**失败原因**（自然语言）/ **错误输出**（等宽，err 色）/ **已排除项**（说明不是权限、不是凭据问题）
- **必须给下一步可选项**：`重试本次工具调用`(主) / 具体排查动作 / `跳过这一步`
- 失败工具要**保留在右栏工具列表**（err 色），可点击回到失败现场

### 5.8 `<Rail>`（右侧辅助面板）

- 顶部四 Tab：**概览 / 工具 / 任务 / 日志**，选中项底部 2px accent 下划线
- **概览**：服务器信息（名称 + 在线 + OS + vCPU + RAM）→ 资源占用（2×2 指标卡，每个含 4px 进度条，按阈值染色）→ 服务状态 → 网络状态 → 快速信息
- **工具**：本次会话工具列表（名称 + 状态 + 耗时）、目标资源卡（`server_id` / 环境 / 模式）、审计记录
- **任务**：任务进度时间线（用左侧竖线 + 圆点，已完成 ok、进行中 accent、失败 err）、审计记录
- **日志**：最近日志、级别筛选、搜索、复制、**在聊天中分析**
- 折叠态：44px 竖条，四个图标竖排 + 底部展开箭头

### 5.9 `<Composer>`

**三行结构**（`--input` 底、`--border2` 边框、11px 圆角）

1. **输入区**：占位符 `描述你想完成的任务，例如：检查 Nginx 502 的原因`
2. **快捷操作行**：`添加文件` `选择服务器` `选择数据库` `添加上下文` `使用终端`（`1px --border` 与输入区分隔）
3. **参数行（`<ComposerControls>`）**，从左到右：
   - **权限档位**（`<PermissionSelector>`，见 5.12）—— **放在该行最左侧**
   - **模型选择**：药丸下拉，显示当前模型名（如 `DeepSeek-V3`）
   - **思考等级**：药丸下拉，`低` / `中` / `高`，默认 `中`
   - **Agent 模式**：四段分段控件 `Auto` / `Plan` / `Execute` / `Review`，选中项 accent 底白字
   - **发送按钮**：30×30、8px 圆角、accent 底；禁用态转 `--border2`

   药丸控件统一规格：高 26px、7px 圆角、`--panel2` 底 + `--border` 边框、11.5px 字号、`white-space:nowrap`。

- **完全访问时**，输入区上方插入 `<DangerBanner>`（见 5.14）
- 下方提示文字**随档位变化**（不是固定文案）：
  | 档位 | 提示 |
  |---|---|
  | 请求审批 | `每次写操作都需要你确认` |
  | 帮我批准 | `L2–L3 自动执行，L4 仍会询问` |
  | 完全访问 | `L0–L4 自动执行，L5 仍会拦截` |
- `disabled` 态（`WAITING_APPROVAL`）：整体 55% 透明度，发送按钮转 `--border2`
- **硬约束**：模型与模式**只能**出现在这里，不得在顶部栏重复出现

### 5.12 `<PermissionSelector>`（权限档位，核心安全控件）

规格依据：需求开发文档 §A6.5。

| Prop | 取值 |
|---|---|
| `perm` | `请求审批` \| `帮我批准` \| `完全访问` |
| `onPerm` | (next) => void —— **升级必须先经 `<EscalationDialog>`，降级直接生效** |

**视觉**

| 档位 | 图标 | 配色 | 提示文案 |
|---|---|---|---|
| 请求审批 | 锁 | `--ok-soft` 底 + `--ok` 文字与描边 | 每次写操作都需要你确认 |
| 帮我批准 | 盾牌+勾 | `--accent-soft` 底 + `--accent` | L2–L3 自动执行，L4 仍会询问 |
| 完全访问 | 盾牌+感叹号 | `--warn-soft` 底 + `--warn`（描边必须实心可见） | L0–L4 自动执行，L5 仍会拦截 |

形态：药丸 + 下拉箭头，位置在参数行最左；文字必须始终显示档位名，**不允许退化为纯图标**。

**交互规则（不对称，必须实现）**

```text
点击 → 下拉三项
  选 低档（或同级）  → 立即生效
  选 高一级（请求审批→帮我批准）→ 轻量确认后生效
  选 完全访问        → 打开 <EscalationDialog>，确认并满足闸门后才生效
```

**状态约束**

- 档位属于**当前会话**；切换会话 / 关闭应用 → 回落该环境默认档
- 完全访问必须带 **30 分钟倒计时**，到点自动回落
- 每次变更写入审计：`who / when / from / to / env / sessionId`

### 5.13 `<EscalationDialog>`（升级确认，Portal 到 body）

规格依据：需求开发文档 §A6.5.3。**这是本产品唯一的"高危确认"界面，必须逐条照做。**

| 区域 | 内容 |
|---|---|
| 标题栏 | 盾牌-感叹号图标 + `开启「完全访问」` + 右侧关闭 ✕（标题用 `--warn`） |
| 引导语 | 「开启后，Agent 将**不再逐项询问**，可直接在你的目标环境执行下列操作。」 |
| **目标环境** | 独立卡片，**错误色（红）边框 + 红底**；显示 `主机名` + `server_id · IP`；右侧「生产环境」红字标签 |
| **将失去的保护** | 错误色卡片，逐条列出并**右侧标注风险等级**：重启服务/重启容器 `L3`、删除文件 `L4`、修改配置文件 `L4`、修改防火墙 / SSH 配置 `L4` |
| **仍然会被拦截** | 普通卡片：`L5 · 不可逆操作`（删除数据库 · 清空数据表 · 重建集群）→ `一律人工确认` |
| **环境名输入** | 仅**生产环境**出现：标签「请输入目标环境名以确认（防误操作）」+ 输入框，placeholder「请输入「生产」」 |
| **勾选框** | 「我已了解上述风险，并确认当前环境可承受不逐项确认的执行」—— **未勾选时确认按钮必须禁用** |
| 两行说明 | ① 30 分钟自动回落 + 切换会话/关闭应用回落 ② 档位变更与期间操作都写审计 |
| 底部按钮 | `取消`（左，默认焦点） / `开启完全访问`（右，错误色实心；未满足闸门时降透明度） |

**硬性行为**

1. **默认焦点在「取消」**，不在确认。
2. 未勾选 / 未填对生产环境名 → 确认按钮 **disabled**，不可点击。
3. 按 `Esc` 关闭 = 取消。
4. 关闭后回到原档位，不产生任何变更。

### 5.14 `<DangerBanner>`（完全访问常驻横幅）

规格依据：需求开发文档 §A6.5.6。

- 位置：**输入框正上方**，与输入框同宽（跟随 composer 的限宽）
- 视觉：`--warn` 描边 + `--warn-soft` 底 + 琥珀文字，盾牌-感叹号图标
- 文案：`完全访问已开启 · 目标 {主机名}（{环境}）`，右侧右对齐显示 **倒计时** `29:41 后自动回落`
- **只在 `perm === '完全访问'` 时渲染**；一旦回落立即消失
- **不允许**用一个小药丸代替它 —— 该档位下 Agent 可不等确认即执行生产变更，提示必须持续可见

## 6. 任务状态 → UI 渲染映射

严格对照需求开发文档 §A7.1。**核心原则：12 个状态只对应 4 种视觉载体。**

| 状态 | 渲染 | 载体 |
|---|---|---|
| `RECEIVED` | 用户气泡入列；输入框禁用 | 消息 |
| `CLASSIFY_TASK` | 不单独呈现，并入步骤链首行 | — |
| `SELECT_CONTEXT` | 顶部上下文条高亮；多目标时加标签 | 上下文条 |
| `PLAN` | 插入可折叠 **PlanCard** | 载体 1 |
| `INSPECT` | 步骤节点转进行中 + 插入 **ToolCard**(spinner) | 载体 2 |
| `ANALYZE` | ToolCard 转完成；不单独呈现 | — |
| `PROPOSE_FIX` | 渲染 Markdown 分析块（标题/列表/表格/风险提示/建议） | 消息 |
| `WAITING_APPROVAL` | 弹 **ApprovalCard**；输入框禁用 | 载体 3 |
| `EXECUTE` | ApprovalCard 收起为"已批准"；插入执行节点 + 终端块；不显示取消以外的操作 | 载体 2 |
| `VERIFY` | 插入验证节点，结果用绿/红徽标 | 载体 1 |
| `REPORT` | 弹 **SummaryCard** | 载体 4 |
| `COMPLETED` | 顶栏状态转 done；输入框恢复 | 顶栏 |
| `FAILED` | **ErrorCard**，含原因 + 重试 | 载体 4 |
| `CANCELLED` | PlanCard 整体置灰 + "已取消" | 载体 1 |
| `TIMEOUT` | 轻量 toast + 步骤节点标红（**不占独立页面**） | toast |
| `WAITING_USER` | 输入框恢复 + 聊天区插提问气泡（**普通消息样式，非确认卡**） | 消息 |

## 7. 与 OpenHands 的对接点（前端侧）

| 前端需要的东西 | 来源 | 注意 |
|---|---|---|
| 会话与消息流 | OpenHands Agent Server REST + WebSocket | 直接用官方 `@openhands/typescript-client`，不要手写协议 |
| 事件流（Action / Observation / 状态变更） | WebSocket 推送 | 前端把事件映射成第 6 节的载体 |
| **审批请求** | `ConfirmationPolicy` 拦截后产生的事件 | 收到即渲染 ApprovalCard；批准/拒绝回传同一会话 |
| 工具调用的 8 个字段 | Action 的参数 + Observation 的输出 + 执行元数据 | 命令与 stdout 在 Observation 里；耗时/风险等级来自执行元数据 |
| 资源树 | **自建 FastAPI** `/api/connections/*` | 注意两个后端并存，客户端要分层封装 |
| 任务进度 | **自建**：从事件流投影出 §A7 的 12 态 | 建议放在自建后端，前端只消费状态 |
| 凭据 | **前端永远不接触** | 界面上只出现 `credential_ref` 的"已配置"状态 |
